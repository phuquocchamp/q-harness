# Agent harnesses for LLM coding agents: inner loop vs outer platform

Research survey compiled 2026-11-09 for **qharness**, an outer harness that drives Claude Code / OpenCode over ACP and exposes CLI tools (supabase, vercel, k8s, github, bitbucket, jenkins) and skills.

**Working definitions used below**

- **Inner harness (agent loop):** the code wrapped directly around the model: tool loop, tool definitions, prompt scaffolding, context/compaction strategy, permission model. Examples: Claude Code, OpenCode, Codex CLI, SWE-agent, OpenHands, mini-SWE-agent.
- **Outer / platform harness:** the layer around one or more inner agents: looping and session orchestration, planner/evaluator roles, gateway to external tools and skills, logging/tracing/visualization, guardrails, evaluation. Examples: Anthropic's long-running-agent harnesses, OpenAI's Codex App Server clients, Ralph loops, Magentic-One's orchestrator, qharness.

Every link below was returned by a web search or fetched directly during this survey. Items marked *(secondary)* were verified only through third-party summaries.

## Design takeaways for qharness

1. **Do not rebuild the inner loop.** Evidence (AgencyBench +20.5% for Opus inside Claude Code SDK; Kimi degrading in foreign scaffolds) says vendor harnesses are tuned to their models. Drive Claude Code / OpenCode as-is over ACP and add value *around* them.
2. **Own state outside the context window.** Follow Anthropic's long-running harness: a JSON feature/task ledger, a progress file, descriptive git commits, an `init.sh`, and a smoke test at session start. Magentic-One's task ledger vs progress ledger is a good schema split.
3. **Loop = session.** Treat each ACP `session/new` + `session/prompt` as one Ralph-style iteration with fresh context; qharness decides termination (ledger all green, budget, max iterations) and carries notes/reflections (Reflexion) into the next prompt.
4. **Separate generator from evaluator.** Run verification as a distinct agent or deterministic check (tests, Playwright, `kubectl rollout status`), since agents overrate their own work; make the evaluator skeptical and feed concrete failures back.
5. **Make harness policy per backend and per model.** Context resets helped Sonnet 4.5 and hurt nothing with Opus 4.5; Cursor removed guardrails as models improved; scaffold-bench reversed sign across models. Keep orchestration config as data, versioned, and A/B-testable.
6. **Build the CLI gateway as an ACI.** Apply SWE-agent's lessons to supabase/vercel/k8s/github/bitbucket/jenkins: compact outputs, pagination, lint-like validation that rejects bad invocations with actionable errors, and short accurate docs (Gorilla). Expose via MCP so any inner agent can use it; load tool definitions lazily (Cursor 2.4) to protect context.
7. **Default-deny privileges.** Progent/AgentSpec-style policies at the gateway: per-skill `allowed-tools`, environment scoping (prod vs staging), confirmation for irreversible actions (tau-bench framing). Enforce at *both* ACP `session/request_permission` and Claude Code `PreToolUse` hooks.
8. **Package operational know-how as Agent Skills.** Use the agentskills.io format (SKILL.md + scripts/ + references/) with progressive disclosure; the 2026 source-code study found skills overtaking MCP in adoption, so skills are the durable unit for "how we deploy here".
9. **One trace tree.** Set `CLAUDE_CODE_ENABLE_TELEMETRY` and the OTLP endpoint for the inner agent, propagate `TRACEPARENT`, and name qharness spans with OTel GenAI conventions (`invoke_agent`, `execute_tool`, `gen_ai.tool.call.id`). Join on `tool_use_id` / `request_id` so gateway calls, permission decisions and model calls line up for visualization.
10. **Give the agent observability, not just the human.** OpenAI's harness exposed logs/metrics/traces and screenshots *to the agent*; qharness can surface jenkins console logs, k8s events, and vercel deploy logs as tools, closing the feedback loop.
11. **Sandbox and audit for exploits.** scaffold-bench showed an agent fetching the upstream fix and deleting held-out tests. Restrict network in eval mode, record full trajectories, and audit for shortcuts before trusting a green ledger.
12. **Measure your own contribution.** Run the same backend bare vs under qharness on SWE-bench Verified / Terminal-Bench with 3+ runs and pass^k; benchmark noise is 2-6 points, so smaller "gains" are not real.
